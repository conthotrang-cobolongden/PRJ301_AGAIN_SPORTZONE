# Admin MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Triển khai Admin MVP gồm Dashboard, quản lý sân, sinh slot theo tuần, booking toàn hệ thống, booking vãng lai, check-in, lazy NoShow và lazy Completed trong tối đa hai phase và hai lượt verification.

**Architecture:** Giữ một WAR Servlet/JSP và mọi route qua `MainController`. Phase 1 hoàn thành toàn bộ schema, DAO và service; Phase 2 chỉ nối controller/JSP và mở luồng booking/payment hiện có cho Admin. Không dùng background thread: trạng thái booking được reconcile bằng SQL có điều kiện trước các request Admin liên quan.

**Tech Stack:** Java 8, Servlet 3.1 (`javax.servlet`), JSP/JSTL, SQL Server, JDBC, NetBeans Ant, Tomcat 9, Bootstrap 5 hiện có.

**Verification budget:** Chính xác hai lượt. Lượt 1 chạy sau Phase 1; lượt 2 chạy sau Phase 2. Viết test trước code nhưng không chạy test đỏ riêng, không chạy test lẻ và không tự phát sinh lượt thứ ba. Nếu một lượt fail, sửa trong cùng lượt rồi chạy lại đúng batch đó; lần chạy lại là phần tiếp tục của lượt đang mở.

- [ ] `AdminCourtDAO` cung cấp đúng hai method:

```java
List<Court> findAll() throws SQLException;
CourtUpdateOutcome updatePriceAndStatus(int courtID, BigDecimal price,
        String status, LocalDateTime now) throws SQLException;
```

`updatePriceAndStatus` mở một transaction, lock court bằng `UPDLOCK, HOLDLOCK`, xác nhận court tồn tại, rồi đếm booking cản trước khi update. `CourtUpdateOutcome` chứa `found`, `updated`, `blockingCount`. Query blocking join `Courts → TimeSlots → Bookings`, status booking thuộc `Pending`, `Confirmed`, `CheckedIn`, và so `DATEADD(DAY, DATEDIFF(DAY, 0, SlotDate), CAST(StartTime AS DATETIME)) > ?`. Vì `BookingDAO.findSlotForUpdate` cũng lock row Courts, booking mới và đổi trạng thái sân được serialize, không có khoảng race giữa count và update.

- [ ] `TimeSlotDAO.generateWeek(LocalDate monday)` mở transaction isolation `SERIALIZABLE` và insert theo `Courts CROSS JOIN` bảy ngày × tám giờ. Dùng `WHERE NOT EXISTS` trên `(CourtID, SlotDate, StartTime)`; status mới là `Available` chỉ khi court `Available`, còn lại `Closed`. Trả `GenerationResult(created, skipped)` với `skipped = 560 - created` vì số sân cố định là 10. Unique constraint hiện có vẫn là lớp bảo vệ cuối cho request đồng thời.

- [ ] `AdminBookingDAO` cung cấp:

```java
int reconcile(LocalDateTime now) throws SQLException;
List<Booking> findAll(String status) throws SQLException;
Booking findDetail(int bookingID) throws SQLException;
List<model.BookingService> findServices(int bookingID) throws SQLException;
boolean checkIn(int bookingID, LocalDateTime earliest,
        LocalDateTime deadline, LocalDateTime now) throws SQLException;
```

- [ ] `reconcile` chạy transaction gồm hai conditional update:

```sql
-- NoShow
UPDATE b SET Status=N'NoShow', UpdatedAt=?
FROM Bookings b JOIN TimeSlots ts ON b.TimeSlotID=ts.TimeSlotID
WHERE b.Status=N'Confirmed'
  AND DATEADD(MINUTE, 30,
      DATEADD(DAY, DATEDIFF(DAY,0,ts.SlotDate), CAST(ts.StartTime AS DATETIME))) <= ?;

-- Completed
UPDATE b SET Status=N'Completed', UpdatedAt=?
FROM Bookings b JOIN TimeSlots ts ON b.TimeSlotID=ts.TimeSlotID
WHERE b.Status=N'CheckedIn'
  AND DATEADD(DAY, DATEDIFF(DAY,0,ts.SlotDate), CAST(ts.EndTime AS DATETIME)) <= ?;
```

- [ ] `checkIn` chỉ update một dòng `Confirmed` khi slot start thỏa `earliest <= now < deadline`; set `Status='CheckedIn'`, `CheckInAt=now`, `UpdatedAt=now`.

- [ ] Mọi booking select Admin bổ sung `a.FullName AS RawAccountName`, `r.RoleName AS AccountRoleName`, và map display name bằng Java: role Admin → `Khách vãng lai`, ngược lại dùng `FullName`.

- [ ] `InvoiceDAO.INVOICE_SELECT` join `Roles` và thay account name bằng:
